# 발주 11 — 수량 필드가 자유 텍스트일 때 던지지 않는다

## 왜

발주 10 산출물을 실데이터 325건에 돌렸더니 306건 성공, **19건이 여전히 예외로 죽는다.**
값을 보니 파서 버그가 아니라 **명세가 틀렸다** — 아래는 전부 정상 데이터다:

```
"드레싱 15g, 덮밥소스 165g"                          × 9
"5g(ml)"                                          × 7
"생·숙면 200g, 건면 100g, 당면 30g, 유탕면(봉지)120g…"  × 3
```

구성요소가 여럿이거나 단위를 병기한 **사람이 읽으라고 쓴 메모**다.
단일 수량으로 안 읽히는 게 당연하다.

**여기서 예외를 던지면 그 항목이 검색 결과에서 통째로 사라진다.**
오늘 잡은 최악의 버그(`SERVING_SIZE='100mL'` 를 던져서 음료 20% 가 조용히 소실)와
**정확히 같은 실패 모드**다. 영양값(`per100g`)은 멀쩡한데 **부가 힌트 하나 때문에 항목을 죽인다.**

## 고칠 것 — 수량 파싱 실패는 `null` 이다

`NUTRI_AMOUNT_SERVING` 과 `Z10500` **양쪽 모두**, **단일 수량으로 읽히지 않으면
예외를 던지지 말고 `null` 로 둔다.** 대신 원문을 버리지 않는다.

반환에 **note 필드 2개**를 추가한다:

```js
{
  // ... 기존 전부 그대로 ...
  totalAmount, totalUnit,
  totalNote,     // string | null   ← 신규
  servingAmount, servingUnit,
  servingNote,   // string | null   ← 신규
}
```

### 규칙

| 원본 값 | amount | unit | note |
|---|---|---|---|
| `'150ml'` | `150` | `'mL'` | `null` |
| `'30g'` | `30` | `'g'` | `null` |
| `'1,000.000g'` | `1000` | `'g'` | `null` |
| `'100'` (단위 없음) | `100` | `null` | `null` |
| `'5g(ml)'` | `null` | `null` | `'5g(ml)'` |
| `'드레싱 15g, 덮밥소스 165g'` | `null` | `null` | `'드레싱 15g, 덮밥소스 165g'` |
| `'약 200g'` | `null` | `null` | `'약 200g'` |
| `'abc'` | `null` | `null` | `'abc'` |
| `'0g'` | `null` | `null` | `'0g'` |
| `'-5g'` | `null` | `null` | `'-5g'` |
| `'  150ml  '` | `150` | `'mL'` | `null` |
| `null` / `undefined` / `''` / `'   '` | `null` | `null` | `null` |
| 문자열 아님 (숫자·객체 등) | — | — | **`TypeError`** ← 이것만 던진다 |

**핵심 변경:** 발주 10 에서 `Error` 로 규정했던 `'0g'`·`'-5g'`·`'약 200g'`·`'abc'` 가
전부 **`null` + note** 가 된다. 타입이 아예 다른 경우(문자열이 아님)만 `TypeError` 로 남긴다 —
그건 응답 구조가 바뀌었다는 뜻이라 조용히 넘기면 안 된다.

- **note 는 원문을 그대로 담는다.** trim 만 하고 가공하지 않는다
- 수량이 정상 파싱되면 note 는 `null` 이다. 둘 다 채우지 않는다
- `'0g'`·`'-5g'` 를 note 로 보내는 이유: 0 이나 음수 중량은 계산에 못 쓰지만
  **데이터가 그렇게 적혀 있다는 사실 자체는 화면에 보여줄 가치가 있다**

### `resolveServing` 은 그대로 둔다

`servingAmount` 가 `null` 이면 이미 `null` 을 반환하게 돼 있다. note 는 보지 않는다.
**「1회분을 모른다」는 판정은 변하지 않는다** — 모르면 개수 입력을 막는다는 규칙 그대로다.

## 테스트 요구사항

- **위 표의 모든 행**을 `Z10500`·`NUTRI_AMOUNT_SERVING` **양쪽에 대해** 테스트한다
- 실제 자유텍스트 3종을 그대로 넣어 잠근다:
  `'5g(ml)'`, `'드레싱 15g, 덮밥소스 165g'`,
  `'생·숙면 200g, 건면 100g, 당면 30g, 유탕면(봉지)120g, 유탕면(용기)80g'`
- **정상 항목이 자유텍스트 때문에 죽지 않는지** 확인하는 테스트를 넣는다 —
  `per100g`·`name`·`basis` 는 그대로 나오고 `servingAmount` 만 `null` 이어야 한다
- 발주 10 이 만든 기존 테스트 중 **`'0g'`·`'-5g'`·`'약 200g'`·`'abc'` 가 던진다고
  단언하는 것들을 새 규칙으로 고친다.** 그 외 기존 테스트는 그대로 통과해야 한다
- `TypeError` 케이스(문자열 아님)는 `assert.throws` 로 남긴다
- 테스트는 표에서 유도한다. 구현을 읽고 베끼지 않는다
