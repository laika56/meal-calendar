# 발주 18 — `unsupported-serving` 결과에 수량과 단위를 실어 보낸다

## 왜

`parseQuickFoodInput('김밥 1개')` 는 지금 이렇게 돌려준다:

```js
{ ok: false, reason: 'unsupported-serving', query: '김밥' }
```

**수량(`1`)과 단위(`개`)를 파싱해놓고 버린다.** 그래서 호출부가 쓸 수가 없다.

이게 문제가 되는 이유: **이제 DB 가 1인분을 안다.** 발주 12 이후
`resolveServing()` 이 김밥 230g, 빅맥 223g 을 알려준다.
호출부는 「검색해서 1인분을 알아낸 뒤 개수를 곱한다」를 하고 싶은데,
개수가 안 넘어와서 못 한다.

**대표 중량을 지어내라는 게 아니다.** 파싱해놓고 버린 값을 그냥 넘겨달라는 것이다.
g 환산은 호출부가 DB 값으로 한다.

## 만들 / 고칠 파일

- `src/lib/quickFoodInput.js` (수정)
- `tests/quickFoodInput.test.js` (보강)

## 고칠 것

`reason: 'unsupported-serving'` 으로 돌려줄 때 **두 필드를 추가**한다.

```js
{ ok: false, reason: 'unsupported-serving', query: '김밥', count: 1, unit: '개' }
```

| 입력 | `count` | `unit` |
|---|---|---|
| `'김밥 1개'` | `1` | `'개'` |
| `'빅맥 2개'` | `2` | `'개'` |
| `'만두 1.5개'` | `1.5` | `'개'` |
| `'라면 한 개'` | `1` | `'개'` |
| `'만두 두 개'` | `2` | `'개'` |
| `'피자 세 개'` | `3` | `'개'` |
| `'치킨 네 개'` | `4` | `'개'` |
| `'케이크 반 개'` | `0.5` | `'개'` |
| `'국 한 공기'` (대표중량 없는 식품 + 공기) | `1` | `'공기'` |
| `'고기 2팩'` | `2` | `'팩'` |
| `'과자 3봉지'` | `3` | `'봉지'` |

- **한글 수사도 숫자로 바꾼다**: `한`=1, `두`=2, `세`=3, `네`=4, `반`=0.5.
  이미 `ok: true` 경로에서 쓰는 변환이 있으면 **그대로 재사용**한다
- `unit` 은 **입력에 나온 그대로** 담는다 (`'개'`, `'공기'`, `'팩'`, `'봉'`, `'봉지'`)
- 다른 `reason`(`'empty'`, `'food-required'`, `'invalid-amount'`, `'quantity-required'`)에는
  **이 두 필드를 넣지 않는다.** 수량을 못 읽은 경우들이다

### 바꾸지 말 것

- **`ok: true` 경로의 반환은 그대로 둔다.** 필드를 더하지도 빼지도 않는다
- `reason` 값들과 판정 조건을 바꾸지 않는다. 지금 `unsupported-serving` 이 나오는 입력은
  그대로 `unsupported-serving` 이어야 한다
- `splitQuickFoodInput`(발주 17)은 건드리지 않는다 — `parsed` 를 그대로 통과시키므로
  자동으로 새 필드가 따라간다

## 테스트 요구사항

- **위 표의 모든 행**을 테스트한다
- **다른 `reason` 에는 `count`/`unit` 이 없는지** 확인한다 (`assert.strictEqual(r.count, undefined)`)
- `ok: true` 인 기존 케이스(`'반숙란 2개'`, `'밥 한 공기'`, `'우유 200g'`)의 반환이
  **한 글자도 안 바뀌었는지** 잠근다 — 회귀 방지가 이 발주에서 제일 중요하다
- 기존 테스트가 전부 그대로 통과해야 한다
- 테스트는 표에서 유도한다. 구현을 읽고 베끼지 않는다
