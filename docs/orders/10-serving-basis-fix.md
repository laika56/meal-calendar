# 발주 10 — 기준 단위·쉼표·1회분 의미 교정 (순수 로직)

## 왜 다시 하는가

발주 09 를 실데이터로 돌려보니 **325건 중 88건(27%)이 파싱에 실패**했다.
원인이 네 가지이고, **그중 둘은 발주 04 때부터 있던 버그로 지금 배포본에 살아 있다.**

| # | 문제 | 규모(표본 325건) | 언제부터 |
|---|---|---|---|
| **A** | `SERVING_SIZE` 가 `'100mL'` 이면 던진다 | **64건 (20%)** | 발주 04 — **라이브 버그** |
| **B** | 숫자에 천단위 쉼표가 오면 실패 (`'1,183.000'`, `'1,380.000g'`) | 24건 | 발주 04 — **라이브 버그** |
| C | `Z10500` 의 `mL` 단위를 거부한다 | 86/502 (17%) | 발주 09 명세 오류 |
| D | `Z10500` 을 「개당 중량」이라고 규정했다 | 전체 | 발주 09 명세 오류 |

**A 가 특히 나쁘다.** 음료·라떼·쉐이크는 전부 `100mL` 기준이라 통째로 버려지는데,
`functions/index.js` 가 항목별 파싱 실패를 건너뛰고 계속하므로 **사용자에게는 그냥
「검색 결과 없음」으로 보인다.** 조용히 20%를 버리고 있었다.

**D 는 위험하다.** `Z10500` 은 **제품 총중량**이지 1회 섭취량이 아니다.
프로틴 파우더 1kg 통이 `'1,000.000g'` 인데 이걸 「1개」로 계산하면 **3,950kcal** 이 찍힌다.
1회 섭취량은 별도 필드 **`NUTRI_AMOUNT_SERVING`** 에 들어 있다 (예: `'150ml'`).

# A. `SERVING_SIZE` — `100mL` 을 받아들인다

지금은 `'100g'` 이 아니면 무조건 던진다. **`'100mL'` 도 정상값이다.**

반환에 **`basis`** 를 추가한다. 영양값이 100g 기준인지 100mL 기준인지 구분한다.

| `item.SERVING_SIZE` | `basis` |
|---|---|
| `'100g'` | `'g'` |
| `'100mL'` | `'mL'` |
| `'100ml'` | `'mL'` — 소문자도 받는다. **반환은 항상 `'mL'` 로 정규화** |
| `' 100g '` | `'g'` — trim |
| `'100'` | **`Error`** — 단위가 없으면 판정 불가 |
| `'50g'` | **`Error`** — 100 기준이 아니면 per100 계산이 깨진다 |
| `null` / `undefined` / `''` | **`Error`** |
| 문자열 아님 | **`Error`** |

기존 `per100g` 키 이름은 **그대로 둔다.** 이름을 바꾸면 호출부가 전부 깨진다 —
값의 기준이 무엇인지는 새 `basis` 필드가 말한다. (이 어긋남은 Claude 가 나중에 정리한다.)

# B. 천단위 쉼표를 허용한다

`parseNutrient` 와 수량 파싱 **양쪽** 모두.

| 입력 | 결과 |
|---|---|
| `'1,183.000'` | `1183` |
| `'1,000.000g'` | `1000` |
| `'2,000.000g'` | `2000` |
| `'275.000'` | `275` |
| `'1,23'` | **`Error`** — 세 자리 묶음이 아니다 |
| `'1,,000'` | **`Error`** |
| `',100'` | **`Error`** |
| `'1,000,'` | **`Error`** |

쉼표는 **세 자리 묶음일 때만** 허용한다: 정수부가 `\d{1,3}(,\d{3})*` 형태여야 한다.
제거는 `replace(/,/g, '')` 로 하되, **먼저 형태를 검사하고 나서 제거**한다.
아무 쉼표나 지우면 `'1,23'` 이 `123` 이 되어 조용히 틀린 값이 된다.

# C·D. 수량 필드 — 이름과 의미를 바로잡는다

발주 09 의 `servingG` 를 **삭제하고** 아래로 대체한다.
(`servingG` 라는 이름 자체가 「1회분 그램수」로 읽혀서 오해를 낳는다.)

```js
{
  foodCode, name, category, per100g,     // 기존 — 변경 금지
  basis,                                  // 'g' | 'mL'          ← A
  maker, isFranchise,                     // 발주 09 — 변경 없음
  totalAmount,   // number | null   제품 총중량/총용량  (Z10500)
  totalUnit,     // 'g' | 'mL' | null
  servingAmount, // number | null   1회 섭취량        (NUTRI_AMOUNT_SERVING)
  servingUnit,   // 'g' | 'mL' | null
}
```

| `item.Z10500` | `totalAmount` | `totalUnit` |
|---|---|---|
| `'292.000g'` | `292` | `'g'` |
| `'35.00g'` | `35` | `'g'` |
| `'1,000.000g'` | `1000` | `'g'` |
| `'650.000mL'` | `650` | `'mL'` |
| `'360.000ml'` | `360` | `'mL'` — 정규화 |
| `'100'` (단위 없음) | `100` | `null` — **던지지 않는다.** 수치는 쓸 수 있고 단위만 모른다 |
| `'  35.00 g '` | `35` | `'g'` |
| `null` / `undefined` / `''` / `'   '` | `null` | `null` |
| `'0g'` | **`Error`** | |
| `'-5g'` | **`Error`** | |
| `'약 200g'` | **`Error`** | |
| `'abc'` | **`Error`** | |
| 문자열 아님 | **`Error`** | |

## `servingAmount` / `servingUnit` — `NUTRI_AMOUNT_SERVING`

**`Z10500` 과 정확히 같은 규칙**으로 파싱한다. 같은 헬퍼를 쓴다.
관측된 값이 `'150ml'` 처럼 소문자 단위이므로 정규화가 반드시 필요하다.

에러 메시지의 필드 이름만 다르게 한다 (`totalAmount` / `servingAmount`).

## 지켜야 할 것

- **`null` 은 정상값이다.** 수량 정보가 없는 항목이 있고, 그건 「개수로 기록 불가」를
  뜻할 뿐 파싱 실패가 아니다
- 에러 메시지에 `FOOD_CD` 를 포함한다
- **`NaN` 을 메시지에 넣을 때 `JSON.stringify` 를 쓰지 않는다.** `JSON.stringify(NaN)` 은
  문자열 `"null"` 을 반환한다. 발주 09 가 만든 `formatValue()` 헬퍼를 그대로 쓴다

# E. `resolveServing(parsed)` — 새 순수 함수

「1개/1회분」이 무엇인지 판정한다. **판정 불가를 판정 불가로 반환하는 게 이 함수의 핵심이다.**

```js
export function resolveServing(parsed)
// → { amount: number, unit: 'g'|'mL', source: 'franchise-total'|'serving-field' }
//  | null
```

| 조건 | 반환 | 근거 |
|---|---|---|
| `isFranchise === true` 이고 `totalAmount` 가 있음 | `{ amount: totalAmount, unit: totalUnit ?? basis, source: 'franchise-total' }` | 외식 메뉴는 총중량이 곧 1인분이다 (표본 261건 전부 `NUTRI_AMOUNT_SERVING` 이 없다) |
| 위가 아니고 `servingAmount` 가 있음 | `{ amount: servingAmount, unit: servingUnit ?? basis, source: 'serving-field' }` | 가공식품은 1회 제공량 필드가 정답이다 |
| 둘 다 없음 | `null` | **모르면 `null` 이다. 총중량으로 대신하지 않는다** |
| `isFranchise === false` 이고 `servingAmount` 없음, `totalAmount` 만 있음 | `null` | 포장 총량이지 1회분이 아니다. 프로틴 1kg 통이 여기 해당한다 |

- 인자가 객체가 아니면 `TypeError`
- **`totalAmount` 를 1회분 대용으로 쓰지 않는다.** 이 규칙을 어기면 프로틴 1kg 통이
  3,950kcal 로 기록된다. 이 함수는 그걸 막으려고 존재한다

## 테스트 요구사항

- **위 모든 표의 모든 행**을 테스트한다. 표가 곧 명세다
- `tests/fixtures/mfds-brand-sample.json` 의 실제 항목으로도 잠근다
  (`버거_빅맥 버거` → `totalAmount: 223, totalUnit: 'g', basis: 'g', isFranchise: true`,
   `resolveServing` → `{ amount: 223, unit: 'g', source: 'franchise-total' }`)
- **`resolveServing` 이 `null` 을 돌려주는 케이스를 반드시 테스트한다** —
  가공식품 + 총중량만 있고 1회제공량 없음 (프로틴 파우더형)
- 경계값: 쉼표 형태 오류 4종, `'0g'`, 음수, 단위 없음, `100mL`, 소문자 `ml`
- `Error`/`TypeError` 는 `assert.throws` 로 잠근다
- **기존 테스트 중 `servingG` 를 참조하는 것은 새 필드로 고친다.** 그 외 기존 테스트는
  그대로 통과해야 한다
- 테스트는 표에서 유도한다. 구현을 읽고 베끼지 않는다
