# 발주 19 — 이름 대조에 제조사(브랜드)를 포함한다

## 왜

`맥도날드 빅맥 1개` 를 치면 **검색은 성공하는데 자동 기록이 안 된다.**

```js
items = [{ name: '버거_빅맥 버거', maker: '맥도날드' }, ...]
hasNameMatch('맥도날드 빅맥', items)  // → false   ← 여기서 막힌다
hasNameMatch('빅맥', items)          // → true
```

**브랜드명이 `name` 이 아니라 `maker` 에 있기 때문이다.**
`hasNameMatch` 는 `name` 만 본다.

`hasNameMatch` 는 「엉뚱한 식품의 영양값이 조용히 들어가는 것」을 막는 안전장치라
없애면 안 된다. **대조 범위에 `maker` 를 넣어서** 브랜드를 앞에 붙인 입력이
정상 통과하게 한다.

배포본 실측(2026-08-14): `김밥 1개, 맥도날드 빅맥 1개, 우유 200g` →
김밥·우유는 들어가고 빅맥만 「못 알아들었다」로 떨어졌다.

## 만들 / 고칠 파일

- `src/lib/quickFoodInput.js` (수정 — `hasNameMatch`, `selectBestFood`)
- `tests/quickFoodInput.test.js` (보강)

## 입력 형태

검색 결과 항목은 이 필드를 갖는다 (발주 09·12 이후):

```js
{ name: '버거_빅맥 버거', maker: '맥도날드' | null, ... }
```

`maker` 는 **`null` 일 수 있다** (일반 식품). 그때는 지금과 똑같이 동작해야 한다.

---

## 1. `hasNameMatch(query, foods)`

**대조 대상을 `name` 에서 `name + ' ' + maker` 로 넓힌다.**

판정 규칙 자체는 바꾸지 않는다 — 지금 `name` 에 대해 쓰는 방식을 그대로
「이름 또는 제조사」에 적용한다.

| `query` | 항목 | 결과 |
|---|---|---|
| `'빅맥'` | `{name:'버거_빅맥 버거', maker:'맥도날드'}` | `true` (지금과 같음) |
| `'맥도날드 빅맥'` | `{name:'버거_빅맥 버거', maker:'맥도날드'}` | **`true`** ← 이 발주의 목적 |
| `'맥도날드'` | `{name:'버거_빅맥 버거', maker:'맥도날드'}` | `true` |
| `'김밥'` | `{name:'김밥', maker:null}` | `true` (지금과 같음) |
| `'서브웨이 샌드위치'` | `{name:'샌드위치_참치', maker:null}` | `false` — 서브웨이가 어디에도 없다 |
| `'빅맥'` | `{name:'김밥', maker:null}` | `false` (지금과 같음) |
| `foods` 가 빈 배열 | — | `false` |

- **여러 토큰이 흩어져 있어도 통과시킨다:** `'맥도날드 빅맥'` 의 토큰 `맥도날드`(maker)와
  `빅맥`(name)이 각각 다른 필드에서 발견돼도 매치로 본다
- `maker` 가 `null`/`undefined` 면 이름만 대조한다 (지금 동작)
- 비교는 **앞뒤 공백 제거 + 내부 연속 공백 1개 + 대소문자 무시**로 정규화하고 한다

## 2. `selectBestFood(query, foods)`

**같은 확장을 적용한다.** 지금 `name` 으로 점수를 매기고 있으면,
`maker` 에서 발견된 토큰도 같은 방식으로 쳐준다.

| `query` | 후보 | 골라야 할 것 |
|---|---|---|
| `'맥도날드 빅맥'` | `버거_빅맥 버거`(맥도날드), `버거_더블빅맥 버거`(맥도날드) | **`버거_빅맥 버거`** — `빅맥` 이 더 정확히 맞는다 |
| `'빅맥'` | 위와 같음 | `버거_빅맥 버거` (지금과 같음) |
| `'맥도날드'` | 위와 같음 | 첫 번째 (구분할 근거가 없다 — 지금 동작 유지) |

**기존 폴백 동작을 바꾸지 않는다.** 아무것도 안 맞으면 지금처럼 `foods[0]` 을 돌려주고,
그 경우를 `hasNameMatch` 가 걸러내는 구조도 그대로다.

## 테스트 요구사항

- **위 두 표의 모든 행**을 테스트한다
- **`maker` 가 `null` 인 기존 케이스가 전부 그대로 동작하는지** 잠근다 — 회귀 방지가 핵심이다
- `'서브웨이 샌드위치'` 가 **`false`** 인지 반드시 잠근다. 서브웨이는 DB 에 없으므로
  샌드위치 결과를 「맞다」고 하면 안 된다 — 브랜드를 넣었다고 아무거나 통과시키면
  이 안전장치가 무의미해진다
- 토큰이 두 필드에 흩어진 경우(`맥도날드`=maker, `빅맥`=name)를 명시적으로 잠근다
- 기존 테스트가 전부 그대로 통과해야 한다
- 테스트는 표에서 유도한다. 구현을 읽고 베끼지 않는다
