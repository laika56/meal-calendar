# 발주 13 — 다중 질의 결과 병합·중복제거·순위 (순수 로직)

## 배경

`buildSearchPlan(query)`(발주 09)이 **최대 4개의 질의 계획**을 돌려준다.
호출부(Cloud Functions)가 이걸 앞에서부터 시도하는데, **결과를 어떻게 합치고 무엇을
위로 올릴지**가 아직 없다. 그 판정을 순수 함수로 만든다.

네트워크는 이 발주의 범위가 아니다 — **이미 받아온 결과 배열을 다루는 로직만** 만든다.

## 만들 파일

- `src/lib/searchResults.js` (신규)
- `tests/searchResults.test.js` (신규)

기존 `src/lib/searchPlan.js`, `src/lib/mfdsParser.js` 스타일을 따른다
(ESM export, 한국어 주석, `TypeError` 로 잘못된 타입 거부).

## 입력 형태

`parseMfdsFoodItem()`(발주 09~12)의 반환을 그대로 쓴다. 이 발주에서 보는 필드만 적는다:

```js
{
  foodCode,     // 'D202-091000000-0015'  — 고유 식별자
  name,         // '버거_빅맥 버거'
  maker,        // '맥도날드' | null
  foodGroup,    // 'dish' | 'processed' | 'ingredient' | 'unknown'
  isFranchise,  // boolean
  // ... 나머지는 그대로 통과시킨다 (건드리지 않는다)
}
```

## 점수 규칙

각 항목에 아래를 **모두 더한다.** 높을수록 위로 온다.

| 조건 | 점수 |
|---|---|
| `name` 이 검색어와 **정확히 일치** (공백 정규화·대소문자 무시) | **+100** |
| `name` 이 검색어로 **시작** | +50 |
| `name` 에 검색어가 **포함** | +25 |
| 검색어의 **토큰 하나라도** `name` 에 포함 | 토큰당 +10 |
| `maker` 에 검색어의 토큰이 포함 | 토큰당 +15 |
| `foodGroup === 'dish'` | +20 |
| `foodGroup === 'ingredient'` | **−20** |

근거:
- **`dish` 가 위로 와야 한다.** 사용자가 `김밥` 을 치면 「김밥 한 줄」을 원하지
  「김밥용 단무지」(원재료성)를 원하지 않는다
- `maker` 가점이 `name` 부분일치보다 높은 이유: `맥도날드 빅맥` 처럼 브랜드를 붙여 쳤을 때
  그 브랜드 항목이 위로 와야 한다

## 정규화

- 검색어·`name`·`maker` 모두 **앞뒤 공백 제거 + 내부 연속 공백 1개**로 맞춘 뒤 비교한다
- 비교는 **대소문자 무시**한다 (`toLowerCase()`)
- `maker` 가 `null` 이면 maker 가점은 0 이다

## 경계 케이스

| 입력 | 반환 |
|---|---|
| `items` 가 빈 배열 | `[]` |
| `query` 가 빈 문자열/공백뿐 | **원본 순서 그대로**(점수 계산 없이 복사본 반환) |
| `items` 가 배열 아님 | `TypeError` |
| `query` 가 문자열 아님 | `TypeError` |
| 항목에 `name` 이 없거나 문자열 아님 | `TypeError` |
| 항목에 `foodGroup` 이 없음 | 그룹 가점 0 으로 계산 (던지지 않는다) |

**원본 배열을 정렬하지 않는다.** `[...items].sort(...)` 로 새 배열을 만든다.

## 테스트 요구사항

- **위 모든 표의 모든 행**을 테스트한다
- **안정 정렬을 명시적으로 잠근다** — 점수가 같은 항목 3개 이상을 넣고 원래 순서가
  유지되는지 확인한다
- **`ingredient` 감점이 실제로 순위를 내리는지** 확인한다 (`dish` 와 나란히 두고 비교)
- **`maker` 가점**: `{ name: '빅맥', maker: '맥도날드' }` 를 `'맥도날드 빅맥'` 으로 검색했을 때
  maker 가 없는 동명 항목보다 위로 오는지
- 점수 계산을 직접 단언하지 말고 **순서로 단언한다** — 점수는 구현 세부다
- `TypeError` 는 `assert.throws` 로 잠근다
- 테스트는 표에서 유도한다. 구현을 읽고 베끼지 않는다
