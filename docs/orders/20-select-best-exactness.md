# 발주 20 — 더 정확히 맞는 후보를 고른다

## 왜

`맥도날드 빅맥 1개` 가 **더블빅맥**으로 붙는다.

배포본 실측(2026-08-14), 검색 결과가 이 순서로 온다:

```js
[ { name: '버거_더블빅맥 버거', maker: '맥도날드' },   // ← selectBestFood 가 이걸 고른다
  { name: '버거_빅맥 버거',     maker: '맥도날드' } ]
```

`빅맥` 이 **두 이름 모두에 부분문자열로 들어 있어서** 점수가 같고, 동점이라 첫 번째를 집는다.

결과가 두 겹으로 나쁘다:

1. **엉뚱한 음식이 기록된다.** 빅맥(223g)을 시켰는데 더블빅맥(292g)이 들어간다
2. 하필 그 항목은 **`fatG`·`carbG` 가 `null`** 이라 저장이 거부되고,
   사용자에게는 「추가 실패」로 보인다. 진짜 빅맥은 영양값이 온전한데도 못 쓴다

## 고칠 것 — 동점일 때 「덜 붙은 것」을 고른다

지금은 부분문자열이면 같은 점수다. **더 정확히 맞는 쪽에 가산점**을 준다.

정규화(앞뒤 공백 제거 · 내부 연속 공백 1개 · 대소문자 무시)한 뒤,
각 후보에 아래를 **모두 적용**하고 가장 높은 것을 고른다.

| 조건 | 가산 |
|---|---|
| 이름이 검색어와 **완전히 같다** | +100 |
| 이름의 **구분자로 나눈 조각** 중 하나가 검색어와 완전히 같다 | +80 |
| 이름이 검색어로 **시작**한다 | +40 |
| 이름에 검색어가 **포함**된다 | +20 |
| 제조사에 검색어의 토큰이 포함된다 | 토큰당 +10 |
| **이름이 짧을수록** | `-(이름 길이)` × 0.1 |

### 구분자

식약처 이름은 `버거_빅맥 버거` 처럼 **`_` 로 분류와 제품명을 나눈다.**
`_` 로 자른 조각과 공백으로 자른 조각을 모두 후보로 본다.

`'버거_빅맥 버거'` → 조각 `['버거', '빅맥 버거', '빅맥', '버거']`

### 왜 길이 감점인가

`빅맥` 을 찾을 때 `버거_빅맥 버거`(10자)와 `버거_더블빅맥 버거`(12자)는
위 규칙까지는 동점이다. **덧붙은 수식어가 적은 쪽이 사용자가 말한 것에 가깝다.**
계수 0.1 은 위 가산점들을 뒤집지 않을 만큼 작아야 한다.

### 예시로 잠글 것

| 검색어 | 후보 (이 순서로 입력) | 골라야 할 것 |
|---|---|---|
| `'맥도날드 빅맥'` | `버거_더블빅맥 버거`(맥도날드), `버거_빅맥 버거`(맥도날드) | **`버거_빅맥 버거`** ← 이 발주의 목적 |
| `'빅맥'` | 위와 같음 | **`버거_빅맥 버거`** |
| `'더블빅맥'` | 위와 같음 | `버거_더블빅맥 버거` |
| `'김밥'` | `김밥_김치`, `김밥`, `김밥_참치` | **`김밥`** — 완전 일치 |
| `'김밥'` | `김밥_김치`, `김밥_참치` | `김밥_김치` — 둘 다 부분일치·동점이면 **첫 번째**(안정성) |
| `'맥도날드'` | 위 버거 둘 | **`버거_빅맥 버거`** — 이름으로는 구분 근거가 없으니 길이 감점이 갈라준다. 덧붙은 수식어가 적은 쪽이다 |
| 후보 1개 | 무엇이든 | 그 하나 |
| 아무것도 안 맞음 | `김밥`, `우유` (검색어 `'빅맥'`) | **`foods[0]`** — 기존 폴백 유지 |

## 지켜야 할 것

- **동점이면 입력 순서를 유지한다** (안정 정렬). 위 다섯째 행(`김밥_김치` vs `김밥_참치`)이
  그걸 잠근다 — 이름 길이가 같아서 길이 감점으로도 안 갈라지는 경우다
- **길이 감점은 모든 후보에 적용한다.** 이름 일치한 것에만 적용하는 식으로 나누지 않는다 —
  그러면 규칙이 두 벌이 되어 예측이 어려워진다
- **폴백을 없애지 않는다.** 아무것도 안 맞으면 지금처럼 `foods[0]` 을 돌려준다 —
  그 경우를 `hasNameMatch` 가 걸러내는 구조가 그대로 성립해야 한다
- `foods` 가 빈 배열이면 지금 동작을 유지한다 (바꾸지 않는다)
- 점수 상수는 **위 표의 값 그대로** 쓴다. 지어내지 않는다

## 테스트 요구사항

- **위 표의 모든 행**을 테스트한다
- **후보 순서를 뒤집어서도** 같은 답이 나오는지 확인한다 (첫째 행을 `[빅맥, 더블빅맥]` 순으로도)
- 점수를 직접 단언하지 말고 **어느 후보가 뽑히는지로** 단언한다 — 점수는 구현 세부다
- `hasNameMatch` 관련 기존 테스트가 전부 그대로 통과해야 한다
- 테스트는 표에서 유도한다. 구현을 읽고 베끼지 않는다
