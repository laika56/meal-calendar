# iOS 실기기 확인 — 비회원/회원 인증

대상: `https://calorie-43692.web.app` (커밋 `d4a0e67` 시점 배포본)
작성: 2026-08-13

데스크톱 Chrome 실측은 끝났다. **여기 있는 것은 데스크톱에서 확인이 불가능한 항목만이다** —
iOS standalone PWA 고유 동작과 iCloud 키체인.

> **왜 이게 남았나:** `autocomplete` 속성을 "장식이 아니라 기능"이라고 설계에 못 박았는데,
> 정작 그게 실제로 키체인을 물리는지는 iOS 사파리에서만 확인된다.
> 실사용 복구율이 여기에 달려 있다 — 비밀번호를 기억하느냐가 아니라 키체인이 잡아주느냐다.

---

## 준비

1. 아이폰 사파리로 `https://calorie-43692.web.app` 접속
2. 공유 → **홈 화면에 추가** → 홈 화면 아이콘으로 실행 (주소창 없는 standalone 상태여야 한다)
3. 기존 세션이 있으면 설정 → 계정 → 로그아웃 (회원일 때만 버튼이 있다)

---

## 1. 키체인 저장 제안 — **이게 제일 중요하다**

게이트에서 **회원가입** 탭 → 이메일/비밀번호 입력 → 회원가입.

- [ ] 비밀번호 칸을 탭했을 때 **"강력한 암호"** 자동 생성 제안이 뜨는가
- [ ] 가입 직후 사파리가 **"암호를 저장하시겠습니까?"** 를 묻는가
- [ ] 저장 후 iOS 설정 → 앱 및 웹사이트 암호 에 `calorie-43692.web.app` 항목이 생겼는가

**안 뜨면 그게 결함이다.** 이 경우 `public/index.html` 의 `autocomplete` 속성이 실제로
살아있는지부터 본다 (`username` / `new-password` / `current-password`).

## 2. 재설치 생존 — 복구 기능의 본체

- [ ] 기록을 하나 남긴다 (아무 날짜, 아무 항목)
- [ ] 홈 화면 아이콘을 **삭제**한다
- [ ] 다시 사파리로 접속 → 홈 화면에 추가 → 실행
- [ ] 게이트가 뜬다 → **로그인** 탭
- [ ] 이메일 칸에서 **키체인 자동완성이 뜨는가** (얼굴인식/지문으로 채워지는가)
- [ ] 로그인 후 **아까 남긴 기록이 그대로 있는가** ← 이게 되면 이 기능은 목적을 달성한 것이다

## 3. standalone 고유 동작

- [ ] 게이트 화면이 노치/홈바에 안 잘리는가 (safe-area)
- [ ] 키보드가 올라올 때 입력칸이 가려지지 않는가
- [ ] 가입/로그인 중 화면이 사파리로 튕겨나가지 않는가 (이메일+비밀번호를 택한 이유가 이거다)

## 4. 인증 메일 링크 — 아직 아무도 확인 못 한 항목

실제로 받을 수 있는 주소로 가입해야 확인된다.

- [ ] 가입 직후 인증 메일이 실제로 도착하는가
- [ ] 메일의 링크를 누르면 인증이 완료되는가
- [ ] **앱으로 돌아와 새로고침하면 "⚠ 이메일 미인증" 경고가 사라지는가**

> 마지막 항목이 핵심이다. `emailVerified` 는 토큰이 갱신돼야 반영된다 —
> 경고가 안 사라지면 토큰 갱신 처리가 빠진 것이다.

## 5. 비밀번호 재설정

- [ ] 게이트 → 로그인 탭 → 이메일 입력 → **비밀번호를 잊었어요**
- [ ] 재설정 메일이 도착하는가
- [ ] 재설정 후 새 비밀번호로 로그인되고 **기록이 그대로인가**
